소개

8년차 프런트엔드 개발자. 대량의 데이터를 다루는 화면의 성능 개선, 여러 팀이 함께 만드는 기능의 API 계약과 연동 규격 정리, 개발 속도를 높이면서도 검증 범위를 지키는 체계 구축에 강점.

이해하기 쉽고 단순한 코드를 지향. 측정으로 병목을 확인한 뒤, 효과에 비해 복잡도가 작은 변경을 선택.

사람의 의도를 바탕으로 스펙 작성부터 설계, 구현, 검증, 머지까지 자동화하는 개발 플랫폼 설계에 관심. AI에게 얼마나 맡길지보다, 사람이 언제 어디까지 개입해야 효과적일지 고민 중.

flex

목표 트리의 첫 화면 표시 개선

사이클 필터와 정렬 때문에 서버가 매 요청마다 전체를 조회한 뒤 잘라 보내던 형식상의 페이지네이션을, FE가 페이지 수만큼 반복 호출하던 구조를 개선. 루트 목표는 한 번에 조회하고 열린 하위 목표는 ID를 모아 병렬 조회. 개인 탭 우선 배치와 현재 분기 기본 필터를 제안하고 BE와 개수 조회를 분리. 단계적 로딩 UI와 TanStack Virtual 가상화 적용.

첫 목록 표시 시간 7초에서 0.5초로 단축

구성원 1,000~2,000명 조직, 코드 내 시간 기록 기준

메리츠증권

검증 체계를 유지한 개발 속도 개선

커밋 검사, 캐시 저장과 복원, 빌드, 이미지 전송 비용을 나눠 실측. 전체 타입 검사는 CI로 옮기고 커밋 단계는 변경 범위 검사로 축소. 전체 빌드 캐시 승계는 용량 증가와 실패로 되돌리고 TypeScript 검사 상태로 범위를 좁힘. 매번 새로 생성되는 CI 러너에서 복원되지 않는 Turbopack 캐시를 비활성화하고, Next.js standalone 런타임이 쓰지 않는 중복 산출물을 이미지에서 제외. 실행되지 않고도 성공으로 끝나던 테스트 경로를 바로잡아 단위테스트 1,773건을 MR 필수 검사로 연결.

커밋 시간 약 30초에서 8초, CI 빌드 잡 380초에서 254초(약 33%), 컨테이너 이미지 260.7MB에서 175.7MB로 단축

CI 빌드 잡은 develop 배포 빌드 58건의 중앙값 비교, 이미지는 ECR 압축 기준

공통 코드와 운영 체계 개선

  • 아이콘 198개를 모두 내려받던 구조를 개별 import로 바꾸는 생성기와 자동 변환 도구 구현. WTS 호환을 유지하며 사용처 전체를 개별 컴포넌트 import로 전환. 모든 화면이 받던 아이콘 공유 청크(gzip 약 24KB)를 없애는 대신, 화면별 중복으로 늘어나는 빌드 전체 용량(약 2.8%)을 감수

  • SSR 부하를 실측해 운영 최소 대수와 HPA 증설 기준 변경
  • Sentry 오류에 배포 버전, 앱 버전, 회원 상태를 보강하고, 진입 직후 오류가 누락되던 문제를 SDK 로드 순서 수정으로 해결
  • 흩어진 팀 개발 문서를 검색 가능한 VitePress 문서 사이트로 구축
